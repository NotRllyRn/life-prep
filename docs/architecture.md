# Architecture and boundaries

## Received-mail selection contract and verification gate

The exact Gmail received filter is `-in:sent -in:drafts`, with no `in:inbox` restriction: archived received messages are included. Spam/trash are excluded by default; do not enable `includeSpamTrash`. Initial sync and explicit 21-day backfill combine the age cutoff with this filter; expired-history recovery removes only the age cutoff. History additions must be checked against current `SENT`, `DRAFT`, `SPAM` and `TRASH` labels before materializing content. Watch hints are not proof that a message qualifies. This is a selection contract, not a full label-state mirror.

Review of the pre-change adapter found date-only/empty listing queries and unfiltered history additions. Implementation must not be claimed until corresponding fixture tests verify list queries and history/recovery exclusions. Existing artifacts are not retroactively cleaned by the contract.

Gmail SDK list/profile/get/history calls paginate and deduplicate additions. Initial cursor is captured before listing; subsequent history catches concurrent arrivals. History 404 causes full received-mail recovery (no age cutoff; retain the exclusions above), not a misleading 21-day replacement. History IDs arrive as strings and SDK uses uint64; code never increments or assumes contiguous IDs. Existing history includes additions only: this is a preparatory event queue, not a full mirror of labels/deletions. Full resync queues previously unseen mail, including old mail. Body extraction prefers text, HTML fallback stays untrusted; broad attachment download/analysis is not implemented.

Account-specific sync locks prevent concurrent cursor movement. One daemon/writer is enforced by a Linux flock. SQLite WAL and transactions atomically insert unique account/message event IDs and cursor. Duplicate hints/replays cannot create duplicate events. JSON materialization is atomic rename after database commit; failure/restart rematerializes from durable body. Database and artifacts contain private content: restrict permissions and encrypt disk/backups. Retention/deletion is operator-managed, not automatic.

Dispatch persists intent before network I/O. Signed payload contains artifact references only, never raw mail. 202 is accepted, not completed. Network/ambiguous responses and crash-in-flight become uncertain and are never automatically replayed. Definite auth rejection is failed and permits explicit retry. Accepted/uncertain runs require an operator-verified completion artifact via receipt. There is no claim of exactly-once Hermes execution. Hermes' transient dedup alone is insufficient. Pause suppresses dispatch, not mailbox ingestion. Daily briefing uses local civil time 08:00 America/Los_Angeles with date-key dedup; startup after 08:00 catches up, no missed-day replay. No timezone-fixed UTC cron.

Only Gmail read-only, PubSub consume and optional local trigger are implemented adapters. Normally available Hermes harness sources (including relevant calendar/course/browser/local records) are already approved for read-only investigation, with relevance judged by the agent rather than a per-source allowlist. The daemon supplies no new connector credentials. New authentication, route-specific tool elevation or operations outside the existing read-only approval still require separate operator approval. Broad behavioral charter is not a sandbox. No external mutations, applications, submissions or communications except designated notices are authorized by it. Readiness/urgency decisions are contextual agent behavior, not invented rules in this daemon.

## Deferred production controls

Production Gmail/PubSub quotas and costs, model/tool-call and elapsed-time budgets, bounded retries, message/body sizes, resync memory, queue/artifact disk ceilings, concurrent-agent limits and overload/backpressure policy are deferred. Retention periods, deletion/expiry, backup lifecycle and receipt/notice evidence retention are also deferred; operator-managed deletion is not an implemented retention policy. No production sizing or load/soak validation is claimed. Define and test these controls before activation. There is no automatic completion bridge; manual verified receipts are the only supplied completion path.
